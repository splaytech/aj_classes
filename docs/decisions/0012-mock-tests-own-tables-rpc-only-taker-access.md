# ADR-0012: Mock tests get their own tables; takers reach them only through server functions

- **Status:** Proposed (2026-11-18, Architect at Stage 2)
- **Source:** `docs/delivery/2026-11-17-mock-tests/02-architecture.md`

## Context

Admins build MCQ mock tests and release them. Every active student, parent and signed-up `user` can take a released test free. Assignments already hold MCQ questions with auto-marking, but they belong to a class, need enrolment (`assignment_visible_to`), key attempts on `students.id` (users and parents have none), and carry hold-results, files, e-mail triggers and the mobile app's contract (ADR-0002, 0003, 0007, 0008).

## Decision

1. **New tables** `mock_tests`, `mock_test_questions`, `mock_test_attempts`, `mock_test_answers`. Attempts key on `profiles.id`. Nothing in the assignment tables or functions changes.
2. **Privileges first:** `revoke all` on the four tables from `anon, authenticated` (pattern `20261024120000_posts.sql:18`). Admins then get RLS policies using `private.is_admin()` (active admin at aal2) plus **column-scoped grants only**: select and delete on tests and questions (delete is policy-limited to drafts, via the freeze trigger); insert and update on title and instructions, and on question content columns. `created_by` is not in the insert grant: it defaults to `auth.uid()`, and `status` defaults to `draft`. `status`, `created_by` and `released_*` are never granted, so they change only inside the release and take-back functions. Tutors and everyone else get nothing.
3. **Takers get no rows from the tables.** The attempt and answer tables have no grant and no policy for `authenticated`. Tests and questions do grant `select` (and the column writes above) to `authenticated`, because admins sign in as that role; for everyone else the admin-only RLS policies (`private.is_admin()`) return no rows, so on `mock_test_questions` the answer key is protected by that select policy alone. **Any future select policy on `mock_test_questions` that lets takers read rows would expose `correct_option` and `explanation`**: give takers a function instead (a pgTAP case pins that the table has only the admin policies). Takers use `security definer` functions that gate on `private.can_take_mock_tests()` as defined in 03 §2.5 (`my_active_role() in ('parent','user') or my_student_id() is not null`). Functions return questions without `correct_option` and `explanation` until the attempt is submitted.
4. **Marking happens in `mock_submit` on the server**, one mark per question, score stored on the attempt. One attempt per person per test (unique key).
5. **State changes** happen only in functions: release and take back here, and closing in Amendment 2 (which supersedes "two functions"); Amendment 1 adds the tag columns, written by column grant, not a state change. Every admin function starts with `if not private.is_admin() then raise` and every new function has execute revoked from `public, anon` and granted to `authenticated` only (pattern `20261007090321_family_functions.sql:683`). Triggers on questions take `for update` on the parent test row (not `for share`, which would let two concurrent adds both pass the count check) and refuse changes when it is released, so a write cannot slip in during release and the 100-question cap holds. Take-back is refused once any attempt is submitted (L-5); it deletes in-progress attempts. Start, save and submit take the test row `for share` and take-back takes it `for update`, so they serialise.

## Consequences

- No coupling to class, enrolment or due-date rules. Assignments and the mobile app are untouched.
- Question-shape rules (2-6 options, one key, length limits) are written a second time in a new check constraint. Accepted: a shared "question" table is a bigger refactor with mobile risk.
- Answer keys reach takers only through functions. The remaining RLS risk is a future taker-facing select policy on `mock_test_questions` (decision 3), pinned by a pgTAP case.
- Later paid tests, retakes, non-MCQ kinds or class links are additive columns and tables. No pricing column now.
- Reversing to "assignments with a flag" after attempts exist means a data migration of attempts.
- **Take-back (ruling L-5, 2026-11-18, amends decision 5):** take-back is allowed while no attempt is submitted, and deletes in-progress attempts and their answers in the same transaction, under the test-row lock. Known limit: once any attempt is submitted the test can't be taken back, so a wrong key is fixed by releasing a corrected new test.
- **Accepted risk (ruling L-6, 2026-11-18):** submitting with no answers reveals every correct option and explanation, so the key is effectively public to any signed-up account. Mock tests are practice only and no credential attaches to a score. Requiring at least one answer before submit is deferred.

## Alternatives rejected

- **Reuse `assignments` with a `kind = 'mock'` flag:** fits users and parents badly (no student row, no class), forces every assignment function, RLS rule, trigger and the mobile contract to branch on the flag.
- **Shared generic `questions` table for both:** cleanest long term, touches live assignment tables and mobile now. Deferred.
- **Taker SELECT policies with column grants hiding the key:** one wrong grant or a `select *` leaks the key; a view per role adds the same risk.
- **Marking in the browser:** needs the key sent first.

## Amendment 1 (2026-11-18): categories (subject, stream, year level)

Source: `docs/delivery/2026-11-18-mock-test-closing/02-architecture.md`. Extends decision 2; decisions 1, 3, 4 and 5 are unchanged.

1. **Four columns on `mock_tests`:** `subject text`, `stream text` (stable keys: a `SUBJECTS` key, a programme slug), `year_levels smallint[] not null default '{}'` and `any_year boolean not null default false`. Null or empty means not set. Years and Any year are mutually exclusive.
2. **Written by column grant, like title and instructions:** insert and update on the four columns to `authenticated`, under the admin-only policies. `status`, `released_*` and `closes_at` stay ungranted. This is an exception to the released-test freeze for these four columns only (categories AC 15, 01-requirement Part B); title, instructions, questions and options stay frozen.
3. **Allowed values:** `private.mock_test_options (kind, key, active)`, no grants, no policies. A guard trigger `private.check_mock_test_tags()` (security definer, `search_path ''`, execute revoked, because it reads that private table) accepts a changed subject or stream only if it is an active option, checks the years (ascending, in range 2 to 12, no NULL elements, one-dimensional and 1-based, not combined with Any year), and on a released test refuses clearing a tag that was set (message `mock_tag_kept`). On UPDATE only (never on INSERT), it reads the current row with `select ... for no key update` and judges on that, not OLD (the trigger takes the same FOR NO KEY UPDATE lock the UPDATE takes, and a transaction never waits on a lock it holds, so there is no self-deadlock). The failure hint is the field name (`subject`, `stream`, `year_levels`). Removing a value is `on conflict (kind, key) do update set active = excluded.active`. A value made inactive stays on the tests that hold it.
4. **Required at release:** `mock_release` raises `mock_tags_missing` when any tag is not set. A `BEFORE UPDATE` trigger also refuses draft to released unless `subject is not null and stream is not null and (any_year or cardinality(year_levels) > 0)`, for every writer, judged on a `for no key update` read of the current tags, not on NEW; `mock_release` uses the same predicate. There is no table check constraint, so untagged tests released before this change keep working. Release-versus-clear ordering is proved by a two-session check, not assumed.
5. **Consequence:** the web constants and the options table are two copies of one list, kept equal by a vitest parity test and a pgTAP test. A list change is a migration plus a constants change.

## Amendment 2 (2026-11-18): closing (closing date and Close now)

Source: `docs/delivery/2026-11-18-mock-test-closing/01-requirement.md` Part A (ACs 1 to 9) and ruling S-1, migration `20261119100000_mock_test_closing.sql`. Amends decision 5; decisions 1 to 4 are unchanged.

1. **One nullable column, `mock_tests.closes_at timestamptz`.** A released test is open while it is null or in the future, and closed from that time on; "Close now" sets it to the current time, so expiry and deactivation are one state. A check keeps it null on drafts. It is **ungranted**: no insert or update grant to `authenticated`, so it changes only in the functions below. Closing is decided on every read; there is no scheduled job.
2. **State changes are four admin functions**, each security definer with `search_path ''`, admin at aal2 (`private.is_admin()`), the test row locked `for update` first, and execute revoked from `public, anon, authenticated`, then granted to `authenticated`:
   1. `mock_release(target, closes default null)` releases a draft, optionally with a future closing time (the one-argument version is dropped, because PostgREST can't choose between overloads);
   2. `mock_set_closing(target, closes)` sets, changes or (with null) clears it on a released test, so a closed test can open again;
   3. `mock_close_now(target)` closes an open released test now, even with submitted attempts; on a test already closed it changes nothing (ruling L-1);
   4. `mock_withdraw(target)` keeps its rule (refused once anyone submitted, ruling L-5) and also clears `closes_at`.
3. **What takers see after closing (ruling S-1):**
   - `mock_tests_for_me` still lists a closed test for a caller whose attempt is submitted, with `closes_at`, so the page can mark it Closed. It is hidden from everyone else.
   - `mock_test_open` returns the result view to that caller and `not_found` (HTTP 404, `private.raise_mock_not_found()`) to everyone else.
   - `mock_start`, `mock_save_answer` and `mock_submit` refuse a closed test with `not_found` for everyone, submitters included (ruling L-2). An in-progress attempt is never auto-submitted.
4. **Time source:** the closed checks and `mock_close_now` use `clock_timestamp()`, not `now()` (the transaction start). A start, save or submit that waited on Close now's row lock re-reads the row and judges it against the real time, so it is refused. A two-session check proves it.
5. **Lock order is unchanged:** the test row first (`for share` in start, save and submit, `for update` in the admin functions), then the attempt row.

## Amendment 3 (2026-11-18): marks, pass mark, percentage and admin results

Source: `docs/delivery/2026-11-18-mock-test-scoring/02-architecture.md`, migration `20261121100000_mock_test_scoring.sql`. Amends decision 4 ("one mark per question") and the admin-sees-no-scores rule of the 2026-11-17 requirement (AC 24, 37) for admins only. Decisions 1 to 3 and 5 are unchanged.

1. **Marks and pass mark are columns.** `mock_test_questions.marks smallint not null default 1 check (marks between 1 and 100)`; `mock_tests.pass_mark smallint check (pass_mark between 1 and 100)`, null meaning no pass mark. Both are written by column grant to `authenticated` under the admin-only policies, like title and instructions. Existing questions read 1 (a constant default: no rewrite, no row trigger).
2. **`score` and `total` on attempts keep their names and types and now mean marks earned and total marks.** `mock_submit` stores sums of `marks` instead of counts. The migration writes no existing attempt row (the only write to the table is the one `mock_submit` already makes, while `submitted_at is null`), so every attempt submitted before it stays exactly as stored; it is true because each old question was worth 1 mark.
3. **Percentage and Pass / Not yet are derived on read, never stored.** Two private SQL helpers (immutable, `strict` so a null score, total or pass mark gives null, `search_path ''`, execute revoked) hold the rules: percentage is `score * 100 / total` in integer division (floor); passed is `score * 100 >= pass_mark * total`, null when there is no pass mark. Every function that returns them calls the helpers; the web does not compute them. This is safe only because of the invariant in point 5.
4. **Admin results are a function, not a view or a grant.** `public.mock_test_results(target uuid)`: security definer, `search_path ''`, `if not private.is_admin() then raise` (admin at aal2), execute revoked from `public, anon, authenticated` then granted to `authenticated`. It returns submitted attempts only: attempt id (as a key), taker name (profile full name, else student roster name, else the web fallback, ruling L-8), submit time, score, total, percentage, passed, and `total_rows` (`count(*) over ()`) so the page can say "showing 1000 of N" instead of truncating silently. The migration ends by revoking execute from `public, anon, authenticated` and granting to `authenticated` for `mock_test_results`, `mock_tests_for_me`, `mock_test_open` and `mock_submit`. It returns no e-mail, no profile id and no answers, and takes no locks. `mock_test_attempts` and `mock_test_answers` keep no grant and no policy (decision 3). Rejected: a view, an admin select policy on attempts, a security definer view.
5. **Freeze.** Marks follow the existing `private.check_mock_question`, which refuses any question write once the test is not a draft; no new trigger. The pass mark follows `private.check_mock_test`, replaced to refuse a changed `pass_mark` on a released test with `mock_released`. Neither belongs to the Amendment 1 tag exception. **Invariant:** marks and the pass mark can change only while the test is a draft, and a draft has never had a submitted attempt, because `mock_withdraw` refuses once anyone has submitted (decision 5, L-5) and attempts reference the test `on delete restrict`. A future "change the pass mark after release" would first need a pass-mark snapshot column on the attempt (additive).
6. **Taker functions.** `mock_test_open` returns per-question `marks` and test-level `total_marks` and `pass_mark` (not results, so allowed before submit), and in the revealed branch only `marks_earned`, `percentage` and `passed`. `mock_tests_for_me` and `mock_submit` return the same derived values for the caller's own attempt. The answer key is still returned only after the caller's own submit.
7. **Numeric limits.** Stored `score` and `total` stay smallint: the maximum is 100 questions of 100 marks, 10,000, against 32,767. All multiplication is done in `int`, because `smallint * smallint` is smallint and `pass_mark * total` can reach 1,000,000. Raising the 100-question cap above 327 requires widening the columns first.
8. **Consequences.** The Results function and the new columns reach the shared hosted database when staging is deployed, and staging and production share it; the change is backward compatible, and production `main` has no mock-test UI, so no old screen can misread marks (ruling L-7: no guard). The results function returns at most the PostgREST row limit (1000) with no pagination in v1, and says so through `total_rows`. A two-session case (a pass-mark write waiting on a release must be refused) is a must-pass gate for point 5. The Privacy Policy line "admins can see your name and mock test scores" is Saurabh's gate before the merge to `main` (ruling L-6).
9. **Known limit (review-5, ruling L-12).** `marks` and `pass_mark` are smallint, so a decimal written directly to the database is rounded, not refused (60.5 is stored as 61). The value still lands in 1 to 100 and only an admin at aal2 can write it; the web accepts digits only.
